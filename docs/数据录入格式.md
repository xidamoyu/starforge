# StarForge 数据录入格式规范

> **用途**：定义"公司沉淀历史商单经验"时需要录入哪些数据、每张表每列怎么写、哪些字段进向量库、哪些必须人工确认。
> **对象**：公司运营 / 商务同学录入；或数据入库管道（意图 ⑧）产出的中间格式。
> **版本**：v1.0（2026-09-21）

---

## 1. 总原则（与铁律一致）

1. **只抽取不生成**：入库的是原始素材里的事实条目，禁止凭空编造。
2. **可溯源**：凡涉及"达人/甲方的脾气、注意事项、经验总结"，必须保留 `source_quote`（原始材料原话），否则无法追溯。
3. **人工确认拦截**：`verified = FALSE` 的条目不参与检索。录入后必须人工确认才生效。
4. **禁止伪精度**：不录入"匹配度/靠谱度"这类无来源评分。`confidence` 只是抽取置信度，不是推荐评分，且仅在 `party_traits` 中出现。

---

## 2. 五张表录入说明

> 字段标记：`必填` = 缺了该行不成立；`进向量库` = 该字段会被语义检索索引；`SQL过滤` = 该字段参与结构化硬过滤。

### 2.1 brands（甲方 / 品牌方）

| 字段 | 类型 | 必填 | 用途 | 说明 |
|---|---|---|---|---|
| brand_id | VARCHAR(16) | ✅ | 主键 | 如 `B001`，全局唯一 |
| brand_name | VARCHAR(128) | ✅ | 展示 | 品牌名 |
| industry | VARCHAR(64) | ✅ | SQL过滤 | 美妆/母婴/食品/3C数码/服饰/宠物/家居 |
| company_size | VARCHAR(32) | — | SQL过滤 | 初创/中型/大型 |
| contact_person | VARCHAR(64) | — | 联系 | 对接人姓名 |
| contact_wechat | VARCHAR(64) | — | 联系 | 微信 |
| cooperation_notes | TEXT | — | **进向量库** | 合作偏好、注意事项、预算风格等自由文本 |

**cooperation_notes 怎么写**：写成完整句子，包含「预算倾向 / 目标人群 / 决策速度 / 内容偏好 / 禁忌」。示例见种子数据 `B001`。

---

### 2.2 creators（达人档案，核心表）

分三类字段：**量化过滤（SQL）**、**文本描述（向量）**、**可信度状态**。

#### 量化过滤字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| creator_id | VARCHAR(16) | ✅ | 主键，如 `C001` |
| nickname | VARCHAR(128) | ✅ | 达人昵称 |
| platform | VARCHAR(32) | ✅ | 抖音/小红书/B站 |
| followers | INTEGER | ✅ | 粉丝数（整数） |
| female_ratio | NUMERIC(4,3) | ✅ | 女性粉丝占比 0.000~1.000 |
| age_18_24_ratio | NUMERIC(4,3) | — | 18-24 岁占比 |
| age_25_34_ratio | NUMERIC(4,3) | — | 25-34 岁占比 |
| avg_views | INTEGER | — | 平均播放量 |
| engagement_rate | NUMERIC(5,4) | — | 互动率（如 0.062） |
| quote_embed_15s | INTEGER | — | 植入 15s 报价（元） |
| quote_embed_30s | INTEGER | — | 植入 30s 报价（元） |
| quote_embed_60s | INTEGER | — | 植入 60s 报价（元） |
| quote_custom | INTEGER | — | 定制整条报价（元） |
| category | VARCHAR(64) | ✅ | 垂类 |
| sub_categories | TEXT[] | — | 细分标签数组 |
| region | VARCHAR(64) | — | 地域 |
| coop_models | TEXT[] | — | `placement`/`custom` 数组，默认二者都支持 |

#### 文本描述字段（全部进向量库）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| profile_text | TEXT | ✅ | 达人画像描述（人设、粉丝结构、风格） |
| content_style | TEXT | — | 内容风格一句话概括 |
| past_brands | TEXT | — | 历史合作品牌 |
| cooperation_history | TEXT | — | **【核心私有资产】** 历史合作情况总结 |

#### 可信度与状态

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| data_source | VARCHAR(32) | — | manual / 采集 |
| verified | BOOLEAN | — | 默认 FALSE，人工确认后 TRUE |
| status | VARCHAR(16) | — | active / 停用 |

**报价约定（双模式，可同时支持）**：
- 植入（placement）：按 `quote_embed_15s/30s/60s` 固定档位，**不是市场浮动价**。
- 定制（custom）：`quote_custom` 整条报价。
- 不涉及直播，无直播字段。

### 2.3 deals（商单记录）

| 字段 | 类型 | 必填 | 用途 | 说明 |
|---|---|---|---|---|
| deal_id | VARCHAR(16) | ✅ | 主键 | 如 `D001` |
| brand_id | VARCHAR(16) | ✅ | 外键 | 关联 brands |
| creator_id | VARCHAR(16) | ✅ | 外键 | 关联 creators |
| title | VARCHAR(256) | ✅ | 展示 | 商单标题 |
| category | VARCHAR(64) | — | SQL过滤 | 垂类 |
| coop_mode | VARCHAR(16) | ✅ | SQL过滤 | `placement`/`custom` |
| embed_duration_sec | INTEGER | — | SQL过滤 | 植入时长（仅 placement） |
| agreed_price | INTEGER | — | SQL过滤 | 成交价 |
| quoted_price | INTEGER | — | SQL过滤 | 报价 |
| revision_count | INTEGER | — | 商务条件 | 约定修改次数 |
| revision_used | INTEGER | — | 商务条件 | 实际用了几次 |
| deliverable | TEXT | — | 商务条件 | 交付内容 |
| exclusive_days | INTEGER | — | 商务条件 | 独家期（天） |
| authorization_scope | VARCHAR(128) | — | 商务条件 | 素材授权范围 |
| signed_date | DATE | — | 排期 | 签约日期 |
| publish_deadline | DATE | — | 排期 | 发布截止 |
| published_date | DATE | — | 排期 | 实际发布 |
| status | VARCHAR(32) | ✅ | SQL过滤 | negotiating/signed/producing/published/settled/cancelled |
| settlement_amount | INTEGER | — | 财务 | 结算金额 |
| requirement_text | TEXT | — | **进向量库** | 甲方原始需求描述 |
| negotiation_notes | TEXT | — | **进向量库** | 谈判过程记录【核心私有资产】 |
| result_views | INTEGER | — | 效果 | 结果播放量 |
| result_engagement | INTEGER | — | 效果 | 结果互动量 |

**状态机约定**：未完成的单（negotiating/signed/producing）**不应有复盘**；settled 后才能写 `deal_reviews`。

---

### 2.4 deal_reviews（商单复盘，核心私有资产）

| 字段 | 类型 | 必填 | 用途 | 说明 |
|---|---|---|---|---|
| review_id | VARCHAR(16) | ✅ | 主键 | 如 `R001` |
| deal_id | VARCHAR(16) | ✅ | 外键 | 关联 deals（须是 settled） |
| reviewer_role | VARCHAR(32) | ✅ | 维度 | `agency`（中介）/`brand`（甲方）/`creator`（达人） |
| rating | INTEGER | — | 参考 | 1~5 |
| content | TEXT | ✅ | **进向量库** | 复盘正文：经验教训、可复用的结论 |

**content 怎么写**：不要只复述过程，要落到"下次怎么做"的可复用经验。同一商单可有多条（agency/brand/creator 三视角），种子数据 D003、D006、D012、D013 有示例。

---

### 2.5 party_traits（达人/甲方脾气与注意事项，最核心私有资产）

| 字段 | 类型 | 必填 | 用途 | 说明 |
|---|---|---|---|---|
| trait_id | VARCHAR(16) | ✅ | 主键 | 如 `T001` |
| party_type | VARCHAR(16) | ✅ | 归属 | `creator`/`brand` |
| party_id | VARCHAR(16) | ✅ | 归属 | 对应 creator_id 或 brand_id |
| trait_category | VARCHAR(32) | ✅ | 分类 | 沟通偏好/改稿态度/排期习惯/付款要求/内容尺度/其他 |
| trait_content | TEXT | ✅ | 内容 | 抽取出的具体条目（一句话） |
| severity | VARCHAR(16) | — | 分级 | `info`/`warning`/`critical` |
| source_deal_id | VARCHAR(16) | — | 溯源 | 来源商单（可为空，见下） |
| source_quote | TEXT | — | **防幻觉关键** | 原始材料原话引用 |
| source_channel | VARCHAR(32) | — | 溯源 | `manual_note`/`screenshot`/`import`/`chat_export` |
| source_ref | TEXT | — | 溯源 | 截图文件路径 / 消息 ID |
| confidence | NUMERIC(3,2) | — | 抽取置信度 | 0~1，**不是推荐评分** |
| verified | BOOLEAN | — | **人工确认拦截** | 仅 TRUE 参与检索 |

**四条硬约束**：

1. `source_quote` 必须保留原文引用（聊天记录 / 复盘笔记原话），禁止用总结代替。
2. `verified = FALSE` 不参与检索，录入后等待人工确认。
3. `trait_content` 是抽取的**事实条目**，不是二次生成的经验总结。
4. `severity = critical` 表示"踩了会出事故"级别的注意事项，应优先展示。

**source_deal_id 可为空的情况**：条目来自非单笔商单的长期观察（如种子数据 `T011`、`T021`），此时 `source_quote` 仍建议保留出处说明。

## 3. 录入流程与人工确认

```
原始素材（聊天记录 / 复盘笔记 / 报价单）
        │
        ▼
LLM 抽取结构化条目（只抽取，不生成）
        │
        ▼
写入表（verified = FALSE）
        │
        ▼
人工确认（核对 source_quote 是否忠实原文）
        │
        ├─ 通过 → verified = TRUE，进入检索
        └─ 不通过 → 修正 / 删除
```

**注意**：
- 只有 `verified = TRUE` 的 `party_traits` 与 `creators` 会进入向量检索。
- 录入是"对外的动作"，按全局拦截机制需人工确认后再写入。

## 5. 与种子数据的对应

种子数据文件 `data/seed_data.json` 顶层键与表一一对应：

```json
{
  "_meta": { ... },
  "brands":       [ ... ],   // → brands
  "creators":     [ ... ],   // → creators
  "deals":        [ ... ],   // → deals
  "deal_reviews": [ ... ],   // → deal_reviews
  "party_traits": [ ... ]    // → party_traits
}
```

> 字段名与表列名**完全一致**（snake_case），`init_db.py` 按字段名直接映射。新增/修改字段时，需同步改三处：`schema.sql`（建表）、`init_db.py`（导入语句）、本文档。

## 6. 最小录入示例

**新增一条达人注意事项（party_traits）**：

```json
{
  "trait_id": "T031",
  "party_type": "creator",
  "party_id": "C001",
  "trait_category": "付款要求",
  "trait_content": "结算需在发布后 3 个工作日内完成",
  "severity": "warning",
  "source_deal_id": "D001",
  "source_quote": "聊天记录原话：「我们这边流程是发完三天内结，晚了就不好约下次了」",
  "source_channel": "manual_note",
  "source_ref": "screenshots/2026-09-21/D001-结算沟通.png",
  "confidence": 0.9,
  "verified": false
}
```

> `verified: false` → 待人工确认，确认后置 `true` 才参与检索。
